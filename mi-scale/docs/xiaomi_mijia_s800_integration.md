# Интеграция XIAOMI MIJIA Body Composition Scale S800 (MJTZC04YM)

Документ предназначен для технической команды, реализующей поддержку новой умной весовой платформы **XIAOMI MIJIA Body Composition Scale S800** (внутренний идентификатор прошивки: `xiaomi.scales.ms116`) в Home Assistant add-on `Xiaomi Mi Scale`. Ниже приведён полный анализ текущего состояния проекта, архитектуры, требований к программному обеспечению, характеристик устройства, а также перечень данных и параметров, необходимых для реализации.

---

## 1. Резюме

- **Цель**: обеспечить корректный приём, обработку и публикацию измерений от S800 через существующую инфраструктуру BLE → MQTT → Home Assistant.
- **Ключевые задачи**:
  - Исследовать формат BLE-пакетов конкретной модели.
  - Расширить логику парсинга и расчёта метрик тела.
  - Обновить конфигурационную схему и документацию.
  - Проверить обратную совместимость и производительность BLE-сканера.
- **Базовые предположения**:
  - S800 продолжает использовать BLE-объявления (advertising) для передачи данных о весе и биоимпедансе.
  - Возможны отличия в UUID сервисов, битовых масках и шифровании относительно поддерживаемых моделей XMTZC0xHM.

### 2.1. Архитектурная схема

```
┌──────────────────┐
│   Home Assistant │
└───────┬──────────┘
        │ MQTT Discovery / Sensors
        ▼
┌──────────────────┐       ┌──────────────────────┐
│ MQTT Broker      │◀─────▶│ Xiaomi Mi Scale add-on│
└──────────────────┘       ├──────────────────────┤
                           │ Xiaomi_Scale.py      │
                           │  • чтение options.json│
                           │  • BleakScanner       │
                           │  • парсинг BLE        │
                           │  • публикация MQTT    │
                           └───────────┬──────────┘
                                       │
                                       ▼
                               BLE устройства (Mi Scale V1/V2)
```

### 2.2. Ключевые особенности кода

1. **Загрузка конфигурации** из `/data/options.json`. Параметры включают `MISCALE_MAC`, `MQTT_HOST`, `MQTT_*`, `USERS`, `HCI_DEV` и т.д.
2. **BLE сканирование**: `BleakScanner` с callback, фильтрующим `advertising_data.service_data` для UUID `0000181b-0000-1000-8000-00805f9b34fb` (V2) и `0000181d-0000-1000-8000-00805f9b34fb` (V1).
3. **Парсинг**: извлечение веса, единиц измерения, флага стабилизации и значения импеданса.
4. **Фильтр повторов**: глобальная переменная `OLD_MEASURE` защищает MQTT от дублирования.
5. **MQTT публикация**: отправка JSON с метриками тела. Discovery-конфигурация публикуется при старте.
6. **Расчёт состава тела**: `Xiaomi_Scale_Body_Metrics.bodyMetrics` использует вес, рост, возраст, пол, импеданс.

## 4. Исследование устройства XIAOMI MIJIA Body Composition Scale S800 (MJTZC04YM)

### 4.1. Общее описание
- Линейка: Mijia Body Composition, поколение S800.
- Аппаратный идентификатор: `MJTZC04YM`.
- Внутреннее обозначение в Mi Home/miot: `xiaomi.scales.ms116`.
- Основное назначение: измерение веса тела, биоимпеданса (коэффициент сопротивления), расчёт состава тела.

### 4.2. Функциональность устройства
- Поддерживает измерение веса с высокой точностью (шаг 50 г или меньше).
- Измеряет биоэлектрический импеданс для расчёта жировой массы, воды, мышц, костной массы и т.д.
- Имеет BLE-модуль для передачи результатов на мобильное приложение Mi Home.
- Вероятно, поддерживает отображение веса на LED-дисплее.
- Предположительно использует автоматическое обнаружение пользователя по весу и истории измерений.

### 4.3. Технические характеристики (подтверждение требуется)

| Параметр | Значение (ожидаемое) | Источник/статус |
|----------|----------------------|-----------------|
| Габариты | ~ 300 × 300 × 22 мм | Сведения с маркетинга; требуется валидация |
| Вес устройства | ~1.5–1.7 кг | Требуется подтверждение |
| Диапазон измерений | 0.05–150 кг | Требуется подтверждение |
| Точность | ±50 г | Требуется подтверждение |
| Питание | 4× AAA или встроенный аккумулятор | Требуется подтверждение |
| Интерфейс связи | Bluetooth Low Energy (BLE 5.0) | Уточняется (у современных устройств BLE 5.x) |
| Рабочая температура | 0–40°C | Требуется подтверждение |
| Совместимость | Mi Home (MiJia), Xiaomi Fit | Подтверждается документацией |

### 4.4. Совместимость с существующими системами
- **Home Assistant**: интеграция через add-on возможна при условии поддержки BLE и MQTT.
- **Mi Home / Xiaomi Fit**: официальная поддержка по умолчанию, но их протоколы могут иметь шифрование/валидаторы.
- **Другие платформы**: возможно использование с OpenMQTTGateway, ESP32 и т.д. при реализации соответствующего парсера.

## 5. Протокол связи и особенности взаимодействия

### 5.1. Общие сведения
- Устройства Xiaomi Body Scale передают данные в BLE-рекламных пакетах (Advertising Data) без активного GATT-соединения.
- Основные UUID сервисов (для предыдущих моделей):
  - `0x181B` – стандартизованный **Body Composition Service** (Mi Scale V2).
  - `0x181D` – **Weight Scale Service** (Mi Scale V1).
- В текущей реализации парсится `service_data`, которая содержит последовательность байтов со следующими полями:

| Смещение | Описание | Пример значения |
|----------|----------|------------------|
| 0-1 | Заголовок (`0x1B18` или `0x1D18`) | `0x1B18` |
| 2 | Управляющий байт 1 (флаги стабилизации, наличие импеданса, единицы измерения) | `0x22` |
| 10-13 | Импеданс (2 байта) | `0x0C0E` (3214 Ом) |
| 14-15 | Вес (2 байта, масштаб `* 0.01`) | `0x0FA0` (4000 = 40.00 кг) |

Для S800 необходимо подтвердить, использует ли устройство тот же формат или применяет **MiOT BLE** (зашифрованные пакеты). Устройства серии `msXXX` нередко используют MiOT proprietary format, в котором присутствуют:
- UUID сервиса `0xFE95` (Mi Beacon).
- Наборы данных с идентификаторами `PID`/`DID` и зашифрованными измерениями.

### 5.2. Возможные сценарии передачи данных S800
1. **Mi Beacon (0xFE95)**: устройство публикует пакеты, совместимые с MiOT (как термометры/датчики). Требуется расшифровка ключом, выданным приложением Mi Home.
2. **Унаследованный формат 0x181B**: совместимость с существующим кодом, возможно изменение позиций байтов.
3. **Комбинированный режим**: два типа пакетов — открытые для веса и зашифрованные для расширенных метрик.

### 5.3. Исследовательские действия
- Сканирование BLE-пакетов через `hcitool lescan` / `bluetoothctl` / пакетные снифферы (nRF Connect, Nordic Sniffer).
- Фиксация `service_data` и `manufacturer_data` при стабилизированном весе.
- Сопоставление битовых масок, подтверждение единиц (`kg`, `lb`, `jin`).
- Выявление, передаётся ли импеданс в открытом виде либо требуется ключ шифрования.
- Проверка наличия дополнительных характеристик (например, синхронизация измерений истории).

## 6. Требования к программному обеспечению

| Компонент | Требование |
|-----------|------------|
| Python | 3.9 (используется базовый образ `python:3.9-slim`) |
| Сторонние библиотеки | `bleak`, `paho-mqtt`, `dbus-fast`, системные `bluez`, `libglib2.0` |
| ОС | Любая, поддерживающая Docker и BLE-стек BlueZ (HassOS, Debian, Ubuntu, etc.) |
| MQTT | Совместимый брокер MQTT 3.1.1+, поддерживающий TLS при необходимости |
| Home Assistant | Версия с поддержкой внешних add-on репозиториев |
| Аппаратный адаптер | BLE-совместимый контроллер (hci0/hciX), доступный контейнеру | 

При интеграции S800, возможны дополнительные требования:
- Наличие **MiOT ключа** (если пакеты шифруются).
- Модернизация зависимости (`bleak >= 0.20`) для поддержки новых BLE-функций.
- Поддержка расширенных MTU, если устройство переходит в GATT-сессию.

## 8. План реализации

1. **Сбор данных**
   - Сниффинг BLE-пакетов при измерении веса разными пользователями, фиксация стабильных значений.
   - Фиксация поведения при нескольких единицах измерения.
   - Выяснение, в каких пакетах приходит биоимпеданс.

2. **Анализ формата**
   - Сопоставление байтов с известными полями (вес, импеданс, единицы, флаги).
   - Пошаговое документирование структуры, разработка тестовых векторов.

3. **Разработка**
   - Расширение `callback` в `Xiaomi_Scale.py`: добавление обработчика для нового UUID/формата.
   - Создание абстракции `parse_measurement(data, model)` для упрощения поддержки других моделей.
   - Добавление новых флагов/единиц измерения, при необходимости.

4. **Конфигурация**
   - При необходимости добавить поле `MISCALE_MODEL` (например, `"S800"`), чтобы пользователи могли явно указать модель.
   - Обновить `config.json` (опционально), документацию по настройке.

5. **Тестирование**
   - Юнит-тесты парсинга (если будет добавлена инфраструктура тестирования).
   - Ручная проверка с реальным устройством: получение данных, публикация в MQTT, отображение в Home Assistant.
   - Проверка обработки нескольких пользователей и веса вне диапазона.

6. **Документация**
   - Обновить `DOCS.md` (раздел поддерживаемых устройств).
   - Добавить раздел о специфике S800, требования к BLE/MQTT.

7. **Ввод в эксплуатацию**
   - Релиз новой версии add-on (например, `0.3.7`), описание изменений в `CHANGELOG.md`.
   - Мониторинг логов у пользователей, сбор обратной связи.

## 10. Риски и меры по их снижению

| Риск | Описание | Митигирующие действия |
|------|----------|-----------------------|
| Шифрование MiOT | Пакеты могут быть зашифрованы; требуется ключ | Изучить официальные приложения, возможные ключи через Mi Home, рассмотреть использование MiOT BLE library |
| Изменение формата пакетов | Формат данных отличается от V1/V2 | Создать модуль парсинга с конфигурируемыми смещениями и масками |
| Ограничения BLE адаптера | Старые адаптеры не поддерживают BLE 5 | Рекомендация по адаптерам, документирование требований |
| Увеличение нагрузки | Добавление новых моделей усложняет код | Рефакторинг парсера, модульные тесты |
| Нестабильность соединения | Одновременное использование Mi Home → потеря пакетов | Добавить ретраи, логирование, документировать ограничение |
